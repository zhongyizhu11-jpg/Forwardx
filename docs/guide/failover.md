# 主备线路

一条转发规则可以配**一条主线路 + 几条备用线路**：平时都走主线路，主线路出问题时自动换到备用线路，主线路恢复后再自动切回来。整个过程由目标机器上的 Agent 自己完成，不需要你盯着。

```text
用户 ──> 入口:端口 ──┬──> 主线路 198.51.100.7:443      平时走这条
                     ├──> 备用 1 198.51.100.8:443     主线路挂了换到这条
                     └──> 备用 2 198.51.100.9:443     备用 1 也挂了再换到这条
```

::: tip 主备线路和「转发组」有什么不一样
- **主备线路**（这一页）：挂在一条转发规则上，入口不变，换的是「转发出去的那一头」。切换由 Agent 在机器上完成，几秒内生效。
- **转发组的故障转移**：换的是「用户连进来的那个入口」，靠改 DNS 解析实现，需要配置 DDNS，见 [DDNS 和故障转移](./ddns.md)。

只想「目标挂了自动换一个」，用主备线路就够了。
:::

## 三步开启 {#quick-start}

1. **新建或编辑一条转发规则**，照常选好线路、填好「目标地址」和「目标端口」。这个目标就是**主线路**。
2. 勾上表单里的 **「主备线路」**。
3. 在 **「备用 1」** 里填一个备用地址，格式是 `地址:端口`，比如 `198.51.100.8:443`。
   - 要多条备用就点「＋ 添加备用线路」，最多 10 条，排在前面的先用。
   - 面板里已经有中转规则的话，可以点「从已有中转里选」，不用自己抄地址。

填完之后，备用线路下面有一句话复述「按现在这套设置，流量会怎么走」，例如：

> 平时都走主线路。主线路出问题（新连接连不上，或连续 60 秒检查不通），就换到备用 1，备用 1 也不行再往下换。主线路恢复后稳定 2 分钟，自动切回来。

确认这句话就是你想要的，点「保存」即可。其余设置都有合适的默认值，收在「高级设置」里，一般不用动。

## 它会怎么切 {#how-it-switches}

| 情况 | 会发生什么 |
| --- | --- |
| 用户新连接连不上当前线路 | **立刻**判这条线路坏了，这个连接当场改走下一条，用户基本无感 |
| 当前线路连续 60 秒检查不通 | 判这条线路坏了，换到下一条能用的（Agent 每 5 秒检查一次） |
| 坏掉的线路恢复了 | 要连续稳定 2 分钟才算好，避免时好时坏来回切 |
| 主线路恢复并稳定 | 默认自动切回主线路（可以在高级设置里关掉） |

「60 秒」「2 分钟」都可以在「高级设置 → 什么时候切」里改。

## 能不能用 {#requirements}

主备线路需要 GOST 来切换线路，所以：

| 规则类型 | 能不能用 |
| --- | --- |
| 隧道转发（GOST 隧道） | 可以 |
| 端口转发（管理员） | 可以。勾上时，转发工具会自动换成 GOST |
| 端口转发（普通用户） | 选管理员开好的 GOST 端口转发可以；普通端口转发不行，界面上会给「改用隧道转发」按钮 |
| 转发链 | 不可以。想要自动换线路，可以用转发组 |
| 协议 | 只支持 TCP。勾上时协议会自动改成 TCP |

用不了的时候，复选框是灰的，旁边会用一句话写明原因；能一键改好的（比如「改用隧道转发」「改回 TCP」）会直接给出按钮。

::: warning Agent 版本
基本的主备切换所有版本都支持；时段表、人工指定、自动择优和探测地址要求目标机器上的 Agent 不低于 **2.2.196**（更老的只按线路顺序切）；从 **2.2.197** 起，Agent 每次心跳都会报告「现在正在走哪条线路」，面板上看到的就是实时状态。Agent 版本不够时，主备面板里会写明是哪一项、要升级到哪个版本。
:::

## 在规则卡上看现在走哪条 {#status}

开了主备的规则，卡片上会多一个 **「主备 · 主线路」** 或 **「主备 · 备用 1」** 这样的标记，表示此刻正在走哪条（Agent 还没报告时显示「主备 2」这样的备用条数）。点它会打开主备面板，可以：

- 看每条线路的地址、哪条是首选、现在实际走的是哪条；
- **人工指定**：临时强制走某一条（比如主线路要维护），选好时长，到点自动交回自动模式；
- **交回自动**：提前结束人工指定。

## 高级设置 {#advanced}

「高级设置」折起来时，右边会列出你改过哪些项；全是默认值时写着「都是默认值，一般不用动」。

### 怎么分配线路

| 选项 | 行为 | 适合 |
| --- | --- | --- |
| 主备（推荐） | 平时只走主线路，出问题才换备用 | 绝大多数情况 |
| 轮流 | 每个新连接轮流走每一条，把流量分摊开 | 几条线路质量差不多，想分摊负载 |
| 随机 | 每个新连接随机挑一条能用的 | 同上 |
| 按访客固定 | 同一个来源 IP 总走同一条 | 需要保持登录状态的服务 |

后三种没有「首选线路」，所以下面的人工指定、时段表、自动择优、最短驻留、切回首选都只对「主备」有效。

### 按什么选（只对主备有效）

从上往下，先对上的那一层说了算：

1. **人工指定**：应急用，强制走某一条，到点自动交回。
2. **时段表**：某个时间段优先走另一条，比如「工作日 18:00–01:00 优先走备用 1」错开晚高峰。
3. **自动择优**：按实测延迟挑明显更快的那条（快 20ms 且快 20%，连续 3 分钟才换，避免来回漂）。
4. **按顺序**：以上都没配时，按「主线路 → 备用 1 → 备用 2 …」。

不管哪一层选中了哪条，那条挂了照样会往下换 —— 选路和健康检查是两件事。编辑框里「此刻」起作用的那一层会有标记，改完不用保存就能看到效果。

### 什么时候切

| 设置 | 默认 | 意思 |
| --- | --- | --- |
| 挂了就切 | 60 秒 | 连续检查不通多久，才判这条线路坏了 |
| 恢复观察 | 120 秒 | 坏掉的线路恢复后，要稳定多久才重新启用 |
| 最短驻留 | 0（不限） | 切过去之后至少走多久，防止在两条好线路之间来回切；当前线路挂了时不受它限制 |
| 恢复后切回首选 | 开 | 关掉的话，切走之后就一直走新的那条，直到它也出问题 |

### 健康检查（探测地址）

Agent 默认直接对线路地址连一次 TCP 来判断它好不好。

- 线路是 iptables/DNAT 这类转发时，这一连就是端到端的，**不用填**探测地址。
- 线路是 gost、realm 这类「中转在本地就把连接收下」的转发时，连得上只说明**中转**活着，不代表中转到落地那一段还通。这时给这条线路填一个**探测地址**，指向能反映整条路径的端口（比如中转上另一个直接转到落地的端口）。

面板能认出你填的备用地址是哪台中转时，会在那一行下面提醒「建议补一个探测目标」，点「去补」就会打开这里。

## 常见问题 {#faq}

### 「主备线路」是灰的，勾不上

看复选框旁边那句话，常见的是：

- 规则是**转发链** —— 转发链不支持，想要自动换线路可以改用转发组；
- 规则是**普通用户的普通端口转发** —— 点「改用隧道转发」；
- 隧道不是 **GOST 隧道** —— 换一条 GOST 隧道。

### 保存时提示「主备线路只支持 TCP」

协议选成了 UDP 或 TCP+UDP。点主备那一块里的「改回 TCP」，或者在上面把协议改成 TCP。

### 备用线路其实已经不通了，面板上却一切正常

多半是中转用的 gost/realm 这类转发：中转自己活着，所以检查一直通过。按上面的[健康检查](#advanced)给它填一个探测地址。

### 主线路已经恢复了，为什么还没切回来

依次检查：

1. 恢复后要稳定满「恢复观察」（默认 2 分钟）才算好；
2. 「恢复后切回首选」是否被关掉了；
3. 是否设置了「最短驻留」，还没走满；
4. 是否正处在「人工指定」或「时段表」指定的时间里。

规则卡上的主备面板会写明此刻是哪一层在决定。
